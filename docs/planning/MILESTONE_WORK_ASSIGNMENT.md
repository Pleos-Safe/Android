# MILESTONE 역할분담

두 사람 모두 피그마에서 맡은 화면을 임시 데이터로 먼저 구현하고, 같은 담당자가 실제 기능까지 연결한다. 각자 자기 화면의 전체·분할·좁은 창(L 계열 참고), 로딩·빈 결과·오류 상태를 맡는다.

## 개발자 A · 일상 주행과 운전습관

장소에 들르지 않은 출퇴근 한 번으로 주행 기록, 운전습관 리포트와 강화 포인트 적립을 시연한다.

### 1. 디자인

- 여정 목록·상세·방문 지도·카드별 기억, 운전습관 리포트와 데이터 부족 화면(F 계열, H07).
- 카드팩 보관함·봉투 개봉·앞면 공개, 소장 컬렉션·상세·대표 전시, 카드 강화와 흔적 복구. 전체 창과 분할 창에서 공용 카드 프레임을 사용한다.
- 온보딩·저장 선택·설정·데이터 관리·삭제(G 계열), 기록 조회 실패와 삭제 결과 재확인(H08·H08D·H08DQ).

### 2. 기능 개발

- 속도·기어·플랫폼 조작 제한을 수신해 공통 차량 상태와 조작 가능 여부를 판단한다. 여정의 시작과 종료, 동의한 주행 기록의 저장·복원을 맡는다.
- 주행 종료 시 이동 시간과 안전점수에 따른 포인트를 정산하고 강화 화면의 잔액에 반영한다.
- 주행 기록 조회와 카드 개봉·컬렉션·대표 전시·강화·흔적 복구를 맡는다. 개별 여정 삭제와 전체 프로필 초기화는 각각의 데이터 범위에 맞춰 처리한다.

## 개발자 B · 장소 탐색과 방문

여행 홈에서 장소 한 곳을 찾아 목적지나 경유지로 추가한다. 도착 후 방문을 확인하고, 해당 장소의 방문팩을 받아 개봉 화면으로 이어간다.

### 1. 디자인

- 여행 홈의 주행 전·주행 중·도착·주차 후 결과(A 계열). 공용 버튼·칩·탭·입력창·헤더·다이얼로그·시트와 공용 지도.
- 장소 추천·목록·상세, 지도·검색·핀·장소 선택, 목적지·경유지 확인과 내비 요청 결과(B 계열).
- 도착 후보·방문 근거·사용자 확인·저장·중복·보류(C01·C02·C03·C04·C05·C05P). 위치·조작 제한·장소·내비 안내와 방문 저장 결과 재확인(H01·H02·H03·H05·H06·H08M·H08MQ·H09).

### 2. 기능 개발

- FusedLocation 위치 연동과 장소 추천·지도 검색·선택을 맡는다. Pleos 에뮬레이터에서 SDK 지원 여부와 위치 권한을 확인하고 위치를 수신한다. 위치를 얻지 못하면 지도에서 직접 탐색할 수 있게 한다. NaviHelper로 목적지·경유지 설정과 경로 조회를 처리한다. [위치 SDK 개발 가이드](https://document.pleos.ai/docs/pleos-only/connect-sdk-pleos/FusedLocation/intro)
- 등록한 거점 근처에 주차하면 방문팩 수령을 제안한다. 수령 결과에서 해당 팩 개봉으로 연결한다.
- 홈에 경로·방문 결과·직전 여정의 운전습관 요약·대표 카드·미개봉 팩을 표시한다. 주차 중 받은 팩에서 봉투 개봉 화면으로 이동한다.

## 두 흐름이 만나는 곳

- 같은 주행에는 하나의 여정 ID를 쓴다. A가 여정을 관리하고 B는 방문이 발생한 여정 ID를 사용한다. A가 기존 차량 상태(VehicleRepository)에서 주차·조작 가능 여부를 판정하면 두 흐름 모두 그 값을 읽는다.
- 방문 수령 기록과 카드팩을 함께 저장한다. 주행 정산은 포인트 원장에, 팩 추첨·앞면 확인·강화는 앨범에 기록한다. 홈·기록·컬렉션이 같은 데이터를 구독한다.
- 디자인 단계에서 예시 여정 ID와 방문팩 수령·강화 결과로 화면을 맞춘다. A의 카드 컴포넌트와 B의 지도 컴포넌트는 양쪽에서 재사용한다. 기능을 개발할 때 A는 장소 방문 없이 출퇴근 한 건으로, B는 예시 여정 ID와 주차 상태로 각자 자기 흐름을 끝까지 확인할 수 있다.
