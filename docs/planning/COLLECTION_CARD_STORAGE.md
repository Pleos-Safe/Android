# 컬렉션 저장 구조와 사용 가이드

## 방문팩 → 컬렉션 → 강화

보상 제공자는 도메인의 `CardAlbumRepository.receivePack(grantId, packType, source, place, journeyId)`를 호출한다. 같은 보상은 재시도 시에도 같은 `grantId`와 획득 정보를 넘겨야 한다. 반환값은 보관함의 팩 ID다. 지도에서 수령할 때에는 `VisitPackRepository.claim`이 장소의 `rewardPack`을 사용해 수령 기록과 밀봉 팩을 한 트랜잭션으로 저장한다. 같은 영수증의 팩 ID는 `reward:visit:<receiptId>`로 고정된다.

| 저장 대상 | 언제 기록하는가 |
| --- | --- |
| `album_print` | 서울 13종, 부산·제주 각 11종, 현대 스튜디오 5종과 E-pit 5종. 현대 팩의 카드는 기본 원화만 사용한다. |
| `album_pack` | 지급할 때 출처·시각·장소·여정을 저장한다. 같은 보상으로 팩을 다시 만들지 않는다. |
| `album_copy` | `open(packId)`에서 한 번만 추첨한다. 같은 종류를 뽑아도 팩마다 소장 번호가 다르다. `reveal(copyId)`가 앞면 확인을 별도로 기록한다. |
| `album_wallet` | 선택한 대표 카드의 소장 번호를 저장한다. |
| `point_transaction` | 주행 적립, 시작 잔액과 강화 지출을 0.5P 단위의 부호 있는 정수로 기록한다. 홈·주행기록·강화가 같은 잔액을 읽는다. |
| `album_action` | 강화·복구 시도별 이전/결과 수치, 소모량, 소모 사본, 결과 확인 여부를 저장한다. |

강화와 복구는 `copyId`, 화면이 본 `revision`, 시도별 `requestId`를 받는다. 판정·차감·레벨·이력은 한 트랜잭션으로 확정하고, 같은 시도를 재전송하면 원래 결과를 돌려준다. 결과 화면을 닫기 전에 앱이 종료되면 다음에 그 결과를 이어서 확인한다. 파괴 시 현재 수치 −5의 흔적이 남으며 최고 수치·획득 정보는 보존한다. 같은 종류·같은 색상의 +0 사본 한 장을 선택해 무료로 복구한다. 복구 재료는 소모 처리 후에도 개봉 이력에 남는다.

보관함에서 **팩 열기**를 누르면 밀봉 봉투를 보는 화면으로 이동할 뿐 추첨하지 않는다. 이 화면에서 **봉투 열기**를 누르면 사본 한 장이 확정되고, **카드 뒤집기**를 눌러 앞면을 확인하면 컬렉션에 표시된다. 중간에 나가거나 앱을 다시 켜도 밀봉 팩은 밀봉 상태로, 이미 개봉한 팩은 같은 사본의 뒷면으로 돌아간다.

Room v6는 주행 v4·컬렉션 v4 및 v5를 같은 스키마로 이관한다. 기존 주행 포인트는 0.5P 단위로 환산하고 이전 앨범의 잔액은 개시 잔액 한 건으로 옮긴다. 기존 방문 수령 기록에 대응하는 미개봉 팩도 한 번만 생성한다. 기존 해운대·광안리의 소장 번호, 획득일, 앞면 확인, 대표 카드, 여행 기억은 새 앨범으로 이어진다. 이전 Lv.1~5는 +0·+5·+10·+15·+20으로 한 번 변환한다. 과거 진화 알림은 현재 강화 대기열에 들어가지 않는다. 원화가 단종된 장소의 과거 방문과 주행 이력은 각각 기록에 남는다.

Room v7은 `membership_term`에 프로필별 구독 시작과 혜택 종료 시각을 기록하고, `point_transaction.membershipBonusHalfPoints`에 주행별 PLUS 추가 적립을 보관한다. 이전 영수증의 보너스는 0이다. 주행 기록 삭제와 구독 관리는 독립적이며 체험 모드 초기화는 체험용 구독도 초기화한다.

## 모듈과 데이터 소유권

`:feature:collection`과 `:feature:forge`는 `:core:domain`의 같은 카드 보관함을 구독한다. `:core:data`가 이 계약을 구현하고 `:core:database`의 Room 트랜잭션으로 변경을 저장한다. 실제 기록과 체험은 서로 다른 암호화 DB를 사용한다.

| 호출 | 저장 결과 |
|---|---|
| `VisitPackRepository.claim` | 등록한 거점에서 주차를 확인한 뒤 호출한다. 지급 기록과 밀봉 팩을 함께 저장하고 같은 방문 요청에는 기존 수령증을 반환한다. |
| `CardAlbumRepository.receivePack` | 방문 외의 보상 제공자가 고유한 지급 ID로 팩을 지급한다. |
| `open` / `reveal` | 개봉에서 추첨 결과를 확정하고 뒤집기에서 앞면 확인 시각을 기록한다. 재진입 시 기존 사본에 이어진다. |
| `enhance` / `acknowledge` | 사본 버전·요청 ID·프로필 세대를 검증한다. 포인트 차감, 현재·최고 강화, 흔적 상태와 결과 영수증이 함께 저장된다. 확인한 영수증은 대기열에서 빠진다. |
| `restore` / `feature` | 같은 도안·색상의 확인된 +0 재료 사본을 소모해 흔적을 복구한다. 대표 전시는 소장 상태의 앞면 확인 사본에서 선택한다. |
| `MembershipRepository` | 상점과 설정이 같은 구독 상태를 관찰한다. 변경 시 프로필과 확인한 이용 기간을 검증한다. |
| `ProgressRepository.recordProgress` | 방문 또는 여정의 원본 기록을 보관한다. 정산 가능 여정의 포인트를 같은 트랜잭션으로 기록한다. |
| `HistoryRepository` / `PlaceRepository` | 여행 기록과 활성 장소를 구독한다. 지도 수집 표시는 앞면을 확인한 실제 소장 사본에서 읽는다. |

## 화면과 동시성

컬렉션과 강화는 `album`의 ViewModel에서 Intent를 받아 앨범 스냅샷을 Flow로 구독한다. 개봉 연출은 `PackOpening`, 강화는 `CardWorkshop`과 `album/forge`, 시각 효과 미리보기는 `album/gallery`에 있다. 홈과 다른 기능에서 같은 영수증을 조회할 수 있다. 버튼을 여러 번 눌러도 같은 요청 ID의 추첨·차감·재료 소비는 한 번만 처리한다. 새 시도는 새 요청 ID를 쓰고, 이전 프로필의 작업은 `generation`으로 거절한다.

## 원화와 지도 거점 추가

1. 풀커버 원화는 세로 2:3으로 준비한다. 지역 카드는 기본·변종을 각각, 현대와 E-pit은 기본 한 장을 등록한다.
2. `regionalPrints`에 고유 도안 ID·분류·등급·원화 키·장소·시리즈 번호를 등록하고 `PrintArtwork.kt`의 Android 리소스 매핑을 맞춘다. 도안/팩 분류와 실제 원화의 개수가 확률 화면과 일치해야 한다.
3. 지도 거점은 `core/data/src/main/assets/collection/catalog.json`에 ID·좌표·인정 반경·이미지 키·지급 팩과 연결 도안 ID를 추가한 뒤 콘텐츠 버전을 올린다. 고양은 현대 팩을 지급한다.
4. 방문 당일 횟수와 장소별 재수령 대기는 수령 성공 시에만 반영한다. 새 도안은 기존 소장 사본의 ID나 추첨 이력을 바꾸지 않는다.

## 데이터 이관과 초기화

단종 전 스키마의 정의·소장 기록은 이전 DB를 읽는 데 사용한다. 기존 사용자에게 이미 지급된 현재 원화의 사본은 강화 방식이나 재시작 횟수와 무관하게 한 번만 이관한다. 과거 방문 날짜는 현대화된 카드 상세의 **여행 기억**에서 확인한다. 전체 데이터 삭제 시에는 선택한 프로필의 세대를 교체한다. 체험 모드 초기화는 체험 DB 안에서만 선물과 예시 주행·팩을 다시 준비한다.
